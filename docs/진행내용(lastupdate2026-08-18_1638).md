## 기능 점검 + 회원 부가 기능 추가 (완료, feature/auth, 커밋 전)

사용자가 요청한 16개 기능을 실제 HTTP 요청으로 하나씩 점검. 6개 구현됨(회원가입/로그인/로그아웃/토큰재발급/대기열 진입/순번조회), 10개 미구현(전부 분담표 8장에서 범위 밖으로 명시된 항목: 회원탈퇴/비밀번호 재설정/이메일 인증/내 정보 조회·수정/관심공연). 이 중 **내 정보 조회/수정/회원 탈퇴 3개는 구현 난이도가 낮아 바로 추가**.

**추가/수정 파일**

| 파일 | 내용 |
|---|---|
| `domains/member/router.py` (신규) | `GET /member/me`, `PATCH /member/me`, `DELETE /member/me` |
| `domains/member/service.py` (신규) | `update_my_info`, `withdraw`(탈퇴 전 비밀번호 재확인) |
| `domains/member/repository.py` | `update_member`, `withdraw_member` 추가 |
| `domains/member/schema.py` | `MemberUpdateRequest`, `MemberWithdrawRequest` 추가 |
| `core/exceptions.py` | `ErrorCode.AUTH_MEMBER_WITHDRAWN`(403) 추가 |
| `domains/auth/service.py` | 탈퇴 회원은 비밀번호가 맞아도 로그인 거부 |
| `deps/auth.py` | `get_current_member`에서 탈퇴 회원은 access 토큰이 유효해도 즉시 차단 |
| `api/v1.py` | `member_router` 등록 |
| `tests/test_member.py` (신규) | 조회/수정/탈퇴 오작동(잘못된 비번) 및 탈퇴 후 토큰·로그인 차단 4개 케이스 |

**설계 포인트:** 회원 탈퇴는 **row 삭제가 아니라 소프트 삭제**(`status=WITHDRAWN`, `withdrawn_at` 기록)이며, 탈취된 access 토큰만으로 탈퇴되지 않도록 비밀번호 재확인을 요구한다. 탈퇴 직후에는 (아직 만료 전인) 기존 access 토큰으로도 더 이상 접근이 안 되도록 `get_current_member`에서 상태를 즉시 확인한다.

**검증:** `pytest tests/` **11개 전부 PASSED**. 추가로 실제 HTTP 흐름으로 재검증: 조회→수정→틀린 비번 탈퇴 시도(401, 여전히 ACTIVE)→정상 탈퇴(204)→같은 토큰으로 접근 시도(403 AUTH_MEMBER_WITHDRAWN)→탈퇴 후 로그인 시도(403 AUTH_MEMBER_WITHDRAWN) 전부 확인.

## 1. 디자인 원칙

- **미니멀**: 장식보다 여백. 그림자·입체 효과는 쓰지 않고 얇은 보더/outline으로만 구획하고 상호작용을 표시한다. (2026-08-20에 호버 그림자+살짝 뜨는 효과를 한 번 넣었다가 "촌스럽다"는 피드백을 받아 다시 걷어냄 — 4번 참고.)
- **파스텔 + 블랙 포인트**: 배경/카드는 파스텔 톤, 실행 버튼(CTA)은 검정 pill 버튼으로 시선을 모은다.
- **채도 낮은 시맨틱 컬러**: 에러/성공/경고도 쨍한 원색이 아니라 파스텔 계열 안에서 채도를 낮춰 튀지 않게 한다.
- **한 종류의 폰트**: Pretendard 하나로 굵기(Weight)만 바꿔가며 위계를 만든다.
- **"데모 티" 안 나게**: 실제 이미지 없이 회색 placeholder만 반복되면 데모처럼 보인다는 피드백(2026-08-20)을 반영 — 공연마다 고유한 그러데이션 포스터 아트(`PlaceholderImage`)를 생성해서 채우고, 목록/상세 페이지에 히어로 배너·카테고리 타일 같은 실제 서비스형 구성 요소를 둔다. 컬러 팔레트와 폰트는 그대로 고정, "미니멀"의 정의를 여백 중심에서 "실제 데이터 이상을 꾸며내지 않는다"로 조정.

## 3. 타이포그래피

- 폰트: **Pretendard** (CDN 적용, `index.html`의 jsdelivr 링크). 참고 레퍼런스의 Urbanist는 한글 미지원이라 대체.
- 굵기 규칙: 제목(h1~h3) Bold, 소제목(h4~h6) SemiBold, 본문/버튼 Medium~Regular.
- 자간: 큰 제목은 살짝 좁게(`-0.01em`), 본문은 기본값.

| Variant | Size | Weight | 용도 |

| h1 | 40px | 700 | 페이지 최상단 타이틀 (거의 안 씀) |
| h2 | 32px | 700 | 섹션 타이틀, 공연 상세 제목 |
| h3 | 28px | 700 | 서브 섹션 |
| h4 | 24px | 600 | 카드 타이틀, 통계 숫자 |
| h5 | 20px | 600 | 리스트 아이템 타이틀 |
| h6 | 18px | 600 | 다이얼로그 타이틀 |

## 4. Radius & Elevation

- **radius는 전부 0이다 — 모든 요소가 각진 사각형.** `tokens.ts`의 `radius` 스케일(`sm/md/lg/xl/pill`)이 전부 `0`으로 고정돼 있고, `theme.ts`가 `MuiButton`/`MuiChip`/`MuiPaper`/`MuiCard`/`MuiOutlinedInput`/`MuiAvatar`/`MuiIconButton`에서 이 토큰들을 참조하므로 버튼·칩·카드·인풋·아바타·아이콘버튼이 전부 자동으로 각지게 나온다. (2026-08-20: 처음엔 pill 버튼/20px 카드/원형 배지·아바타 등으로 둥글게 갔었는데, "그림자에 이어 radius 때문에도 촌스럽다, 차라리 전부 사각형으로 가자"는 피드백을 받고 전면 폐지함.) **새 컴포넌트를 만들 때 절대 `borderRadius`를 직접 주지 말 것** — 필요하면 항상 `radius.xxx` 토큰이나 `0`을 참조해서, 나중에 누가 실수로 다시 둥글게 되돌리는 걸 방지한다.
- **그림자는 어디에도 쓰지 않는다.** 기본 상태든 호버든 항상 `1px solid`(`Gray 100`) 보더로만 구획한다. (2026-08-20에 호버 시 `box-shadow` + `translateY(-2px)`로 뜨는 효과를 한 번 넣었다가 "그림자·입체 효과 때문에 촌스러워 보인다"는 피드백을 받고 전부 되돌림 — `PerformanceCard`/`MyReservationsPage`/`SupportListPage`의 호버는 지금 `borderColor` 변화만 준다. 앞으로도 "실제 서비스 같은 입체감"을 이유로 그림자를 다시 추가하지 말 것.)

## 5. 컴포넌트 가이드

- **Primary 버튼**: 검정(`primary.main`) 채움 + 흰 텍스트, 각진 사각형. "예매하기", "회원가입", "로그인" 등 화면당 핵심 액션 1개에만 사용.
- **Secondary/Outlined 버튼**: 흰 배경 + 얇은 그레이 보더 + 검정 텍스트. "공유하기", "취소" 등 보조 액션.
- **필터 Chip**: 미선택 상태는 outlined, 선택된 상태는 `primary` 채움(검정) — 참고 레퍼런스의 "Today/This Week/This Month" 필터 패턴과 동일.
- **통계/하이라이트 카드**: 배경은 액센트 Soft 컬러(blueSoft/greenSoft/yellowSoft) 중 하나, 보더 없이 radius만. 숫자는 `h4`, 라벨은 `subtitle2` + `text.secondary`.
- **일반 콘텐츠 카드**: 흰 배경 + `Gray 100` 1px 보더, 그림자 없음.
- **비밀번호 입력**: 항상 `src/components/common/PasswordField.tsx`를 쓴다. 눈 모양 아이콘으로 표시/숨김 토글 (기본은 숨김).
- **포스터 아트 자리표시자(`PlaceholderImage`)**: 실제 공연 이미지가 없을 때, "이미지 없음" 회색 박스 대신 시드(보통 공연 id)로 매번 같은 그러데이션을 생성해서 채운다. 카드마다 색이 달라야 "진짜 서비스"처럼 보인다는 게 핵심이라, 반드시 카드별 고유값(id 등)을 `seed`로 넘길 것 — 같은 시드를 여러 카드에 재사용하면 전부 같은 색이 나와서 원래 문제가 재발한다.
- **히어로 배너**(`PerformanceListPage`의 `HeroBanner`, `PerformanceDetailPage` 상단): `PlaceholderImage`를 `fill`로 배경에 깔고 `linear-gradient(to top, rgba(20,18,24,0.8)…)` 오버레이 위에 흰 텍스트를 얹는 패턴. 목록 페이지는 상위 2개 공연을 나란히, 상세 페이지는 공연 하나를 전체 폭으로.
- **카테고리 타일**: 칩 대신 아이콘 + 라벨을 세로로 쌓은 각진 사각 배지(원형 아니었던 적도 있었지만 지금은 radius 0으로 통일). 카테고리 목록 조회 API가 없어서 지금 불러온 데이터에서 집계한 값만 쓴다 — 없는 카테고리를 미리 만들어두지 않는다.

## 6. 좌석 상태 컬러 (예매 전용)

MUI 팔레트가 아니라 `tokens.ts`의 `seat` 객체를 좌석 배치도 컴포넌트에서 직접 참조한다 (좌석 상태는 브랜드 컬러 체계와 분리된 전용 규칙이 필요해서).

| 상태 | 배경 | 보더/텍스트 |
|---|---|---|
| 선택 중 (내가 선택, SELECTED) | Eerie Black | 텍스트 White |
| 선점 중 (다른 사용자, HELD) | Gray 50 | 보더 Gray 200, 텍스트 Gray 400 |
| 예매 완료 (RESERVED) | Gray 100 | 텍스트 Gray 300 |

**예매 가능(AVAILABLE) 좌석은 고정 색 하나가 아니라 좌석 등급별로 색이 다르다** — `components/reservations/gradeColor.ts`가 공연의 `seatGrades`를 가격 높은 순으로 훑어서 액센트 컬러(Vanilla → Alice Blue → Honeydew 순)를 배정한다. 등급 이름(VIP/R/S 등)은 백엔드가 자유롭게 정하므로 이름이 아니라 "가격 순서"로 매핑하는 게 핵심 — 등급이 몇 개든, 이름이 뭐든 항상 같은 순서로 톤이 배정된다. 좌석 배치도 위쪽에 `SeatGradeLegend`로 등급·가격을 색상 스와치와 함께 보여준다.

좌석 셀은 `border-radius: 3px`의 단순한 사각형이다(그림자·쿠션 효과 없음). 실 데이터 기준 배치도가 45열까지 나올 수 있어(예: VIP/R/S 각 15열이 한 행에 나란히) 셀 크기를 18px, 간격을 2px로 작게 잡아 가로 스크롤 없이 한 화면에 들어오게 한다(`SeatGrid.tsx`의 `CELL`/`GAP`/`LABEL_W` 상수). 좌석 번호는 셀 안에 표시하지 않고 `title` 툴팁으로만 제공 — 18px 셀에 두 자리 숫자를 넣으면 오히려 지저분해 보여서 뺐다. 무대는 각진 배너 대신 곡선 SVG(`StageArc`, `SeatGrid.tsx` 내부)로 표현한다.

서버가 주는 좌석 `x`/`y`는 그리드 인덱스가 아니라 실제 배치 좌표(20px 단위 절대값)라서, `SeatGrid.tsx`는 좌석들이 실제로 쓰는 x/y 값만 뽑아 순번을 매겨 촘촘한 그리드 인덱스로 변환한 뒤 그린다(그대로 쓰면 열이 수백 개인 초대형 그리드가 됨).

## 7. 반응형 브레이크포인트

MUI 기본 브레이크포인트를 그대로 사용한다 (`xs:0, sm:600, md:900, lg:1200, xl:1536`).

- **모바일(`xs`~`sm`)**: 좌석 배치도는 가로 스크롤 컨테이너 안에서 pinch-zoom, 하단 고정 바에 선택 좌석 요약 + CTA 버튼.
- **데스크톱(`md` 이상)**: figma 와이어프레임과 동일한 1440 기준 레이아웃을 그대로 넓혀 사용.
- 공연 목록 카드 그리드: `xs=1열, sm=2열, md=3열, lg=4열`.

## 8. 로그인 필요 UX 규칙

- 비로그인 상태에서 로그인이 필요한 액션(예매하기, 마이페이지 등)을 누르면 **버튼을 비활성화하지 않고**, "로그인이 필요합니다" 모달을 띄운 뒤 로그인 페이지로 유도한다.
- 모달에는 취소(현재 화면 유지)와 로그인하러 가기 두 개의 액션만 둔다.

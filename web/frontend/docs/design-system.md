## 1. 디자인 원칙

- **미니멀**: 장식보다 여백. 그림자는 거의 안 쓰고 얇은 보더로 구획을 나눈다.
- **파스텔 + 블랙 포인트**: 배경/카드는 파스텔 톤, 실행 버튼(CTA)은 검정 pill 버튼으로 시선을 모은다.
- **채도 낮은 시맨틱 컬러**: 에러/성공/경고도 쨍한 원색이 아니라 파스텔 계열 안에서 채도를 낮춰 튀지 않게 한다.
- **한 종류의 폰트**: Pretendard 하나로 굵기(Weight)만 바꿔가며 위계를 만든다.

## 3. 타이포그래피

- 폰트: **Pretendard** (CDN 적용, `index.html`의 jsdelivr 링크). 참고 레퍼런스의 Urbanist는 한글 미지원이라 대체.
- 굵기 규칙: 제목(h1~h3) Bold, 소제목(h4~h6) SemiBold, 본문/버튼 Medium~Regular.
- 자간: 큰 제목은 살짝 좁게(`-0.01em`), 본문은 기본값.

| Variant | Size | Weight | 용도 |
|---|---|---|---|
| h1 | 40px | 700 | 페이지 최상단 타이틀 (거의 안 씀) |
| h2 | 32px | 700 | 섹션 타이틀, 공연 상세 제목 |
| h3 | 28px | 700 | 서브 섹션 |
| h4 | 24px | 600 | 카드 타이틀, 통계 숫자 |
| h5 | 20px | 600 | 리스트 아이템 타이틀 |
| h6 | 18px | 600 | 다이얼로그 타이틀 |
| body1 | 15px | 400 | 기본 본문 |
| body2 | 14px | 400 | 보조 설명 |
| caption | 12px | 400 | 타임스탬프, 안내 문구 |
| button | 15px | 600 | 버튼 텍스트, 대문자 변환 없음 |

## 4. Radius & Elevation

- **인풋(TextField)과 버튼/칩은 같은 radius 토큰(`999px`, pill)을 쓴다.** border-radius는 요소 높이의 절반을 넘지 못하고 자동으로 clamp되므로, 인풋처럼 높이가 있는 요소도 같은 값을 주면 버튼과 동일하게 "완전히 둥근" 톤으로 보인다. 값 자체를 다르게 관리하면 나중에 둘 중 하나만 바뀌는 불일치가 또 생기니, 반드시 같은 토큰을 참조할 것.
- 카드/패널 radius: `20px`
- 그림자는 원칙적으로 쓰지 않는다. 구획은 `1px solid`(`Gray 100`) 보더로 구분한다. 꼭 필요할 때만 아주 약한 그림자(`0 1px 2px rgba(0,0,0,0.04)`)를 예외적으로 허용.

## 5. 컴포넌트 가이드

- **Primary 버튼**: 검정(`primary.main`) 채움 + 흰 텍스트, pill 형태. "예매하기", "회원가입", "로그인" 등 화면당 핵심 액션 1개에만 사용.
- **Secondary/Outlined 버튼**: 흰 배경 + 얇은 그레이 보더 + 검정 텍스트. "공유하기", "취소" 등 보조 액션.
- **필터 Chip**: 미선택 상태는 outlined, 선택된 상태는 `primary` 채움(검정) — 참고 레퍼런스의 "Today/This Week/This Month" 필터 패턴과 동일.
- **통계/하이라이트 카드**: 배경은 액센트 Soft 컬러(blueSoft/greenSoft/yellowSoft) 중 하나, 보더 없이 radius만. 숫자는 `h4`, 라벨은 `subtitle2` + `text.secondary`.
- **일반 콘텐츠 카드**: 흰 배경 + `Gray 100` 1px 보더, 그림자 없음.
- **비밀번호 입력**: 항상 `src/components/common/PasswordField.tsx`를 쓴다. 눈 모양 아이콘으로 표시/숨김 토글 (기본은 숨김).

## 6. 좌석 상태 컬러 (예매 전용)

MUI 팔레트가 아니라 `tokens.ts`의 `seat` 객체를 좌석 배치도 컴포넌트에서 직접 참조한다 (좌석 상태는 브랜드 컬러 체계와 분리된 전용 규칙이 필요해서).

| 상태 | 배경 | 보더/텍스트 |
|---|---|---|
| 선택 중 (내가 선택, SELECTED) | Eerie Black | 텍스트 White |
| 선점 중 (다른 사용자, HELD) | Gray 50 | 보더 Gray 200, 텍스트 Gray 400 |
| 예매 완료 (RESERVED) | Gray 100 | 텍스트 Gray 300 |

**예매 가능(AVAILABLE) 좌석은 고정 색 하나가 아니라 좌석 등급별로 색이 다르다** — `components/reservations/gradeColor.ts`가 공연의 `seatGrades`를 가격 높은 순으로 훑어서 액센트 컬러(Vanilla → Alice Blue → Honeydew 순)를 배정한다. 등급 이름(VIP/R/S 등)은 백엔드가 자유롭게 정하므로 이름이 아니라 "가격 순서"로 매핑하는 게 핵심 — 등급이 몇 개든, 이름이 뭐든 항상 같은 순서로 톤이 배정된다. 좌석 배치도 위쪽에 `SeatGradeLegend`로 등급·가격을 색상 스와치와 함께 보여준다.

좌석 셀 모양은 순수 사각형이 아니라 `border-radius: 10px 10px 4px 4px` + 상단 하이라이트(`inset box-shadow`)로 좌석 쿠션처럼 보이게 하고, 무대는 각진 배너 대신 곡선 SVG(`StageArc`, `SeatGrid.tsx` 내부)로 표현한다 — 배치도가 밋밋해 보인다는 피드백(`docs/ui_ref/seat_ref*.png`)을 반영한 결정.

## 7. 반응형 브레이크포인트

MUI 기본 브레이크포인트를 그대로 사용한다 (`xs:0, sm:600, md:900, lg:1200, xl:1536`).

- **모바일(`xs`~`sm`)**: 좌석 배치도는 가로 스크롤 컨테이너 안에서 pinch-zoom, 하단 고정 바에 선택 좌석 요약 + CTA 버튼.
- **데스크톱(`md` 이상)**: figma 와이어프레임과 동일한 1440 기준 레이아웃을 그대로 넓혀 사용.
- 공연 목록 카드 그리드: `xs=1열, sm=2열, md=3열, lg=4열`.

## 8. 로그인 필요 UX 규칙

- 비로그인 상태에서 로그인이 필요한 액션(예매하기, 마이페이지 등)을 누르면 **버튼을 비활성화하지 않고**, "로그인이 필요합니다" 모달을 띄운 뒤 로그인 페이지로 유도한다.
- 모달에는 취소(현재 화면 유지)와 로그인하러 가기 두 개의 액션만 둔다.

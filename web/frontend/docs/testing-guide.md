# 프론트 개발/테스트 가이드

> `feature/ui` 브랜치를 pull 받은 팀원이 "이걸 어떻게 켜서 뭘 눌러보면 되는지" 알 수 있게 정리한 문서.
> 백엔드 API가 아직 없는 상태라, 모든 데이터는 **MSW(Mock Service Worker)** 가 브라우저에서 실제 fetch를 가로채서 응답합니다. 새로고침하면 데이터가 초기화되는 인메모리 mock입니다.

## 1. 실행 방법

```bash
cd web/frontend
npm install
npm run dev
```

브라우저에서 `http://localhost:5173` 접속.

```bash
npm run build   # 타입체크 + 프로덕션 빌드
npm run lint    # oxlint
```

## 2. 테스트 계정

목업 DB(`src/mocks/db.ts`)에 미리 심어둔 계정입니다. 새로고침해도 유지되지만(모듈이 재실행되므로 사실은 초기값으로 리셋), **페이지를 완전히 새로고침(F5)하면 그 사이에 가입한 계정은 사라지고 이 계정만 남습니다.**

## 3. Mock API 동작 원리

- `src/mocks/handlers/`에 화면(도메인)별로 핸들러 파일을 나눠 추가합니다. 실제 API 스펙(구글시트 `api 설계서` 탭 / `notion/api-contract.md`)의 endpoint·요청/응답 형식을 그대로 따릅니다.
- 개발 모드(`npm run dev`)에서만 자동으로 켜집니다 (`src/main.tsx`의 `enableMocking()`). 프로덕션 빌드에는 포함되지 않습니다.
- 콘솔에 `[MSW] Mocking enabled`가 뜨고, 이후 API 요청마다 `[MSW] ... (200 OK)` 형태의 로그 그룹이 남습니다 — **API 요청/응답을 확인할 때 브라우저 개발자도구 콘솔을 펼쳐보는 게 제일 빠릅니다.**
- 이메일 인증코드, 비밀번호 재설정 인증코드처럼 "실제로는 이메일로 오는" 값은 전부 **브라우저 콘솔에 `[mock] ... 인증코드: 123456` 형태로 출력**됩니다. 실제 이메일이 발송되지 않으니 콘솔에서 코드를 복사해서 입력하세요.

## 4. 화면별 테스트 시나리오

### 로그인 (`/login`)
1. `test@example.com` / `passwd123` 입력 후 로그인
2. 헤더 우측이 로그인/회원가입 버튼 → 아바타 메뉴로 바뀌는지 확인
3. 잘못된 비밀번호 입력 시 "이메일 또는 비밀번호가 올바르지 않습니다" 에러가 뜨는지 확인

### 회원가입 (`/signup`)
1. 새 이메일 입력 → "인증번호 발송" 클릭
2. 브라우저 콘솔에서 `[mock] {이메일} 인증코드: 123456` 확인 후 그 값을 인증번호 칸에 입력
3. 닉네임(2~20자) / 비밀번호(8자 이상, 영문+숫자 포함) / 비밀번호 확인 입력 후 제출
4. `/login`으로 이동하는지, 방금 만든 계정으로 로그인이 되는지 확인 (탭을 새로고침하지 않은 상태에서)

### 비밀번호 재설정 (`/password/reset`)
1. `test@example.com` 입력 → "인증번호 발송"
2. 콘솔에서 재설정 인증코드 확인 후 입력
3. 새 비밀번호 입력 후 제출 → `/login`으로 이동
4. 바뀐 비밀번호로 로그인되는지 확인 (테스트 후 다시 `passwd123`으로 되돌리려면 같은 과정을 반복하거나 새로고침으로 mock DB를 초기화)

## 5. 트러블슈팅

**"요청에 실패했습니다" 같은 뭉뚱그려진 에러가 뜬다면:**
1. **새 Phase를 pull 받은 직후라면 `npm install`부터 다시 하고, `npm run dev`를 껐다가 다시 켜세요.** 새 npm 패키지가 추가된 상태에서 기존에 켜져 있던 dev 서버를 그대로 쓰면, Vite의 의존성 사전 번들링이 꼬여서 새로 추가된 화면의 API 요청이 실패하는 경우가 있습니다. (실제로 이 문제로 로그인이 막힌 사례가 있었습니다 — 원인은 코드 버그가 아니라 dev 서버를 재시작하지 않아서였습니다.)
2. 브라우저 개발자도구 콘솔을 열고 `[MSW] Mocking enabled`가 찍혀 있는지 확인합니다. 안 보인다면 **강력 새로고침(Ctrl+Shift+R / Cmd+Shift+R)** 후 다시 시도하세요.
3. 그래도 안 되면 개발자도구 Network 탭에서 실패한 `/api/v1/...` 요청의 응답이 JSON인지 HTML(404 페이지)인지 확인해주세요. HTML이 온다면 MSW가 그 요청을 가로채지 못했다는 뜻입니다 — 1번 방법으로 해결됩니다.

**콘솔에 뜨는 인증코드를 못 찾겠다면:** 문자열 `[mock]`으로 검색(콘솔 필터)하면 바로 찾을 수 있습니다.
